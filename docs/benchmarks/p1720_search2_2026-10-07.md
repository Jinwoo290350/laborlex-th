# #17/#20 clean-positive search v2 (2026-10-07) — local only, no Gemini, no code/config change

Definition (Frank, 2026-10-07), four dimensions, each must be supported by the court's findings/reasoning (an allegation
alone = UNKNOWN):
1. refusal: the employee actually refused / did not comply with the order
2. lawful_basis: the order is supported by agreement / work rule / regulation / consent (court-accepted fact)
3. non_obstructive: court reasoning supports that the order was not meant to obstruct demand activity (exact words not required)
4. protection_context: the judgment gives a real basis for the s.31 / s.123 path (#17/#20 live only there; s.52-only is not it)

Classes: CLEAN POSITIVE = 4/4 · PARTIAL/DIAGNOSTIC = refusal + lawful basis, but 3 or 4 unknown · LIMITATION = court holds
the order lawful on a basis outside staging's predicate (agreement/rules/consent) · NEGATIVE = facts contradict a condition.

## Method
All 3,591 rulings in the Legal Index (`cases.full_text`, Thai digits normalised). Filter (scratchpad `p1720_search2.py`):
refusal∧order within 400 chars · agreement/work rule/consent∧order within 300 · union/demand/committee/s.31/123/52 present ·
protection term∧dismissal within 600 → **101 hits** (5 already reviewed). Second pass: genuine LRA s.31/52/121/123 reference
(statute name adjacent) or ≥ 3 union-context terms → 59; triage of holdings and refusal passages; **full text read for 21**.
Near-duplicate check vs dev100 (local bge-m3): all ≤ 0.684. None of the rulings appears in data/eval, docs, prompts or tests.
Leakage rank needs the frozen question text → measured only for 2911/2528 and 3211/2545 so far.
